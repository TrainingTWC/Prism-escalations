Why this exists

Not every finding deserves a ticket

A single audit can fail dozens of checkpoints across many sections. The naïve approach — one ticket per failed section, or worse, per checkpoint — buries the real escalations under noise. This algorithm separates signal from housekeeping.

✗ The old way

One ticket per failed section. A 70%-passing audit could still spawn 8–12 tickets — most of them low-priority paperwork that drown out the one critical safety issue.

✓ The new way

Critical & high findings get dedicated tickets. Everything minor collapses into a single roll-up. Recurrences merge into the existing open ticket. Same audit → 1–3 focused tickets.

Step 1 · Classify

Severity decides the shape

For each failed section, severity comes from the AI analysis (ai.severity) or is computed from the deduction percentage. That severity determines whether the section becomes its own ticket or gets bundled.

Critical own ticket

Marked critical, or a critical checkpoint failed.

→ 1 dedicated ticket · SLA 30 min

High own ticket

Deduction ≥ 60% of the section's score.

→ 1 dedicated ticket · SLA 2 hrs

Medium roll-up

Deduction ≥ 30%.

→ bundled into roll-up · SLA 24 hrs

Low roll-up

Minor deduction below 30%.

→ bundled into roll-up · SLA 72 hrs
🤖

If the AI sets shouldCreateTicket: false on a section, it is skipped entirely — the algorithm respects the model's judgement that the finding doesn't warrant a ticket.

Step 2 · Group

How a payload becomes tickets

Each section flows through the same gate. Critical/high branch off as individual tickets; medium/low pool together into exactly one roll-up per audit (severity capped at medium so it never outranks a real escalation).

Step 3 · Deduplicate

Recurrence merges, it doesn't duplicate

When the same issue reappears at the same store and an open ticket already exists (status not resolved / closed), the algorithm updates that ticket instead of creating a twin.

On mergeWhat happens
SeverityEscalated to the higher of the two (max rank)
Recurrence noteAppended to the description with timestamp + submission ref
DeductionsNew section deductions appended to the JSON history
reopen_countIncremented by 1
Pattern flagRaised — marks it as a recurring problem
SLA deadlineClock restarts only if severity escalated
🔑

Match keys: individual tickets match on store_code + section_id; roll-ups match on store_code + program_id (their section id is the shared sentinel __rollup__).
